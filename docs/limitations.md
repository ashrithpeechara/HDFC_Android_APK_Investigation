# Investigation Limitations

## 1. Purpose

This document records the limitations, constraints and unresolved questions associated with the HDFC Android APK investigation.

The investigation identified multiple security-sensitive capabilities through static application analysis and passive infrastructure intelligence.

However, identifying functionality in application code does not establish that the functionality was successfully executed, that information reached a remote server, or that a device or individual was affected.

These limitations must be considered when interpreting the investigation findings.

---

## 2. Dynamic Analysis Limitations

**Status: Not performed**

The investigation was limited to static APK examination and infrastructure intelligence.

The application was not executed in an Android emulator or on a physical test device as part of this investigation phase.

Consequently, the following behaviours remain unverified:

- Actual application startup and runtime execution.
- Runtime permission requests and permission acquisition.
- SMS collection from an active device.
- Successful SMS forwarding.
- Remote SMS transmission.
- FCM command reception and execution.
- Device information transmission.
- USSD command execution.
- Call-forwarding modification.
- Runtime persistence after device reboot.
- Actual anti-analysis response when instrumentation is detected.

**Impact on assessment:**

The investigation establishes the presence of relevant code paths but cannot confirm their operational effectiveness.

---

## 3. Device and Forensic Acquisition Limitations

**Status: No live victim-device acquisition conducted in this investigation phase**

No live victim Android device was acquired or examined as part of this investigation.

Therefore, the following evidence was not established:

- Whether the application was installed on a victim device.
- Whether the application was granted sensitive permissions.
- Whether SMS messages were accessed.
- Whether outgoing SMS messages were generated by the application.
- Whether call-forwarding settings were modified.
- Whether USSD operations were executed.
- Whether application data or device logs contain evidence of actual activity.
- Whether a particular individual or device experienced compromise.

**Impact on assessment:**

The findings describe application capabilities and configured infrastructure, not confirmed victim-device activity or compromise.

---

## 4. SMS and Communication Limitations

The application contains multiple SMS-related code paths, including financial SMS filtering, historical inbox queries, HTTP forwarding and phone-number-based forwarding.

However, the investigation did not establish:

- Successful collection of actual SMS messages.
- Successful delivery of SMS content to the configured HTTP endpoint.
- Successful delivery of SMS content to the configured phone number.
- Successful execution of remote SMS-sending jobs.
- Actual SMS delivery to intended recipients.
- Server-side storage or processing of SMS information.

A response containing a forwarding number and status was observed from the configured number-retrieval endpoint.

The returned personal information has been redacted from public documentation. Its ownership, device association and intended purpose remain unknown.

**Impact on assessment:**

The identified code presents a potential exposure of sensitive financial communications, but actual data transmission and recipient identity have not been established.

---

## 5. Firebase and Remote Command Limitations

The primary application contains Firebase Cloud Messaging configuration and command handlers for operations including SMS retrieval, SMS sending, USSD execution and device status management.

The investigation did not establish:

- Ownership or administrative control of the Firebase project.
- Successful FCM token registration.
- Successful server-side token storage.
- Actual FCM message delivery.
- The identity of any command sender.
- Successful execution of remotely initiated commands.
- The existence or contents of a corresponding backend command database.

**Impact on assessment:**

The code demonstrates a remote command-handling architecture, but no live command-and-control session was verified.

---

## 6. USSD and Call-Forwarding Limitations

The application contains code for submitting USSD requests and handling call-forwarding configuration.

However, actual carrier-side behaviour was not tested.

The following remain unknown:

- Whether the relevant USSD commands were successfully submitted.
- Whether the mobile network operator accepted the commands.
- Whether the target SIM supported the requested operation.
- Whether call-forwarding settings changed.
- Whether the application received a successful USSD response.
- Whether a configured remote status update was successfully delivered.

Android version, device implementation, SIM selection and carrier support may affect the behaviour of these operations.

**Impact on assessment:**

The investigation identifies potentially sensitive telephony functionality but does not establish successful call interception, redirection or modification of carrier settings.

---

## 7. Embedded APK Limitations

An encrypted asset named `rmtley9lr.db` was recovered and decoded into a secondary APK.

The decoded package was identified as `com.nxtwave.support`.

Although the secondary APK was examined separately, the investigation did not establish:

- Whether the primary application installs the secondary APK.
- Whether the primary application dynamically loads it.
- Whether the secondary APK is executed.
- Whether the two applications exchange runtime data.
- Whether the secondary application performs additional operations during normal execution.

The presence of the embedded APK and a shared signing certificate is not sufficient to prove an execution relationship.

**Impact on assessment:**

The secondary APK is a relevant recovered artifact, but its operational role remains unresolved.

---

## 8. Native Anti-Analysis Limitations

The native ARM64 library contains checks associated with Frida, Xposed, Substrate, Gadget indicators, process memory maps, debugger tracing and instrumentation-related ports.

However, the investigation did not dynamically evaluate:

- Whether these checks execute during application startup.
- Whether they successfully detect instrumentation.
- Whether detection terminates the application.
- Whether detection changes application behaviour.
- Whether the checks can be bypassed.

**Impact on assessment:**

The presence of anti-analysis-related code is established, but its runtime effectiveness is unknown.

---

## 9. Infrastructure Intelligence Limitations

Infrastructure intelligence was collected using DNS, RDAP, TLS certificate, Certificate Transparency and HTTP observations.

The following limitations apply.

### 9.1 DNS

- DNS results represent observations at a specific collection time.
- DNS records may change.
- Cloudflare edge addresses do not establish origin-server addresses.
- DNS resolution does not prove backend ownership.

### 9.2 Domain Registration

- RDAP records provide registration-related information, not necessarily the identity of an application operator.
- Registrar abuse-contact information must not be confused with registrant information.
- An unavailable RDAP response does not establish the complete historical registration status of a domain.

### 9.3 TLS and Certificate Transparency

- Certificate issuance does not establish malicious activity.
- Shared certificate authorities do not establish common ownership.
- Similar hostname patterns do not independently establish common control.
- The collected Certificate Transparency dataset was not exhaustive.

### 9.4 HTTP Endpoint Observations

Some configured endpoints returned HTTP 200 during collection.

An HTTP 200 response establishes only that an HTTP response with that status was returned.

It does not prove:

- Successful backend processing.
- Successful application operations.
- Data persistence.
- Database writes.
- Successful device registration.
- Successful SMS or USSD operations.

### 9.5 Infrastructure Attribution

The investigation did not establish:

- The verified origin server behind Cloudflare.
- The infrastructure operator's identity.
- The application developer's identity.
- The relationship between the domain registrant and application developer.
- Common ownership of all observed hostnames.
- The identity or location of any threat actor.

**Impact on assessment:**

The infrastructure findings provide technical context and indicators for defensive monitoring, but they do not support definitive operator attribution.

---

## 10. Threat Intelligence Limitations

The investigation did not identify a verified public threat-intelligence attribution connecting the examined package, hashes, domains or Firebase identifiers to a specific malware family or threat actor.

The absence of an indexed public match must not be interpreted as evidence that an artifact is benign.

The following remain unresolved:

- Malware family attribution.
- Threat actor attribution.
- Campaign identification.
- Infrastructure ownership.
- Relationship with other known malware samples.
- Confirmed victim count.
- Confirmed financial loss.

**Impact on assessment:**

The classification in this repository is based on examined application capabilities and observed infrastructure, not a confirmed malware-family attribution.

---

## 11. Evidence and Reproducibility Limitations

The repository documents the investigation findings and supporting technical observations.

However, not every original artifact, command output or raw evidence file is included in the public repository.

Sensitive information, authentication-related values and private evidence are intentionally excluded or redacted.

Reproducibility may therefore be limited by:

- Unavailable original artifacts.
- Redacted sensitive values.
- Changes in remote infrastructure.
- Changes in DNS and certificate records.
- Unavailable third-party intelligence records.
- Tool and environment version differences.

The original evidence and investigation records should be maintained separately, with cryptographic hashes and provenance information recorded where available.

---

## 12. Unresolved Questions

The following questions remain outside the established findings:

| ID | Unresolved question |
|---|---|
| UQ-01 | Does the application successfully execute all identified SMS-related functionality? |
| UQ-02 | Does the remote infrastructure receive or store transmitted SMS information? |
| UQ-03 | Are FCM commands actually delivered to installed application instances? |
| UQ-04 | Does the application successfully execute remote SMS-sending jobs? |
| UQ-05 | Can the call-forwarding functionality successfully modify carrier settings? |
| UQ-06 | Does the embedded APK have an active execution relationship with the primary application? |
| UQ-07 | What is the verified origin infrastructure behind the observed Cloudflare-proxied domains? |
| UQ-08 | Who controls the application and associated infrastructure? |
| UQ-09 | Has any individual or organisation experienced confirmed compromise or financial loss? |
| UQ-10 | Can the identified artifacts be associated with a known malware family or campaign? |

These are unresolved questions, not established findings.

---

## 13. Overall Assessment Boundary

The investigation supports the following conclusions:

| Assessment | Status |
|---|---|
| Sensitive functionality present in application code | Established |
| Configured remote endpoints identified | Established |
| Embedded secondary APK recovered | Established |
| Infrastructure observations collected | Established |
| Successful SMS exfiltration | Not established |
| Successful remote command execution | Not established |
| Successful call forwarding or USSD execution | Not established |
| Server-side data storage | Not established |
| Victim-device compromise | Not established |
| Financial loss | Not established |
| Threat actor attribution | Not established |

The application remains classified as **highly suspicious and potentially unauthorised financial-service impersonation software** based on the available technical evidence.

This classification is an investigative assessment and should not be interpreted as proof of actual victim impact or operator identity.

---

## 14. Conclusion

The investigation identified multiple security-sensitive capabilities in the examined Android application and documented its configured remote infrastructure.

However, the absence of dynamic analysis, live victim-device acquisition and verified backend evidence limits conclusions about actual execution and impact.

These limitations are an essential part of the investigation record. They ensure that technical findings remain evidence-based, reproducible where possible and free from unsupported assumptions.
